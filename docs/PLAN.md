# 히든 워드 웹게임 기획안

친구끼리 하는 실시간 멀티플레이 단어 유사도 게임. 데블스 플랜 3(데드 어게인) 5일차 메인 매치 "히든 워드"의 규칙 구조를 참고했다.

> 원작 규칙은 나무위키 요약을 웹 검색으로 확인한 범위다. 원문을 직접 확인하지 못한 부분(유사도 공개 범위, 피스 사용처)은 방 설정 옵션으로 둔다.

## 1. 게임 규칙

- **목표:** 내 히든 워드는 숨기고, 다른 사람의 히든 워드를 맞힌다.
- **라운드:** 2라운드. 라운드마다 모든 플레이어가 한 번씩 출제자가 된다. 출제 순서는 추첨.
- **단어 받기:** 명사 5개가 든 봉투 6개 중 하나를 고르고, 그중 1개를 1라운드 히든 워드로 정한다. 2라운드에는 같은 봉투에서 다른 단어를 고른다.
- **힌트 만들기:** 출제자는 15분 안에 힌트 후보를 최대 10개 입력한다. 입력할 때마다 정답과의 유사도(0~100)가 나온다.
  - 유사도가 95 이상인 단어가 나오면 그 단어가 바로 힌트로 정해진다.
  - 10개 안에 없으면 유사도가 가장 높은 단어가 힌트로 공개된다.
- **맞히기:** 힌트가 공개되면 출제자를 뺀 모두가 동시에 몰래 정답을 적고, 한꺼번에 공개한다.
  - 맞힌 사람은 +1점을 받고, 그 출제자의 차례가 끝난다.
  - 아무도 못 맞히면 출제자가 점수를 받고 다음 힌트로 넘어간다. 1차 1점, 2차 2점, 3차 3점. 힌트는 최대 3차까지.
- **피스:** 피스 1개로 단어를 하나 더 적을 수 있다. 힌트 후보에 쓸지 정답에 쓸지는 방 설정으로 정한다.
- **결과:** 원작은 1·2위 생활동, 3~5위 감옥동, 6위 탈락. 친구용으로는 순위표와 벌칙 문구(직접 입력)로 연출한다.

### 방 설정 옵션
인원(3~8), 제한시간, 힌트 후보 개수, 자동 종료 기준(기본 95), 다른 사람에게 유사도 공개 여부, 피스 사용처와 개수, 고유명사 허용 여부, 직접 입력한 봉투 단어 사용 여부.

## 2. 방 종류

| | 일반방 (무료) | 고유명사방 |
|---|---|---|
| 단어 | 일반명사만 (원작 규칙) | 고유명사, 신조어 허용 |
| 유사도 엔진 | Claude Haiku 5.5. 비용이 커지면 미리 계산한 임베딩으로 전환 | Claude (모델은 테스트 후 결정) |
| 이용 | 무료, 광고 | 출시 때는 하루 N판 무료 베타. 수요가 확인되면 방장 1명이 사는 이용권으로 유료화 (예: 1판 ₩1,000, 1일권 ₩3,000) |

## 3. 아키텍처

```
[브라우저: 사이트 화면]  ← Cloudflare Worker가 정적 파일로 함께 서비스
     │  ① 방·플레이어 상태 동기화          ② 힌트 단어 제출 (Firebase 로그인 토큰 첨부)
     ▼                                      ▼
[Firebase Realtime DB] ◀──결과 기록── [Cloudflare Worker API] ──▶ [Claude API]
   (방, 점수, 공개 정보)                 (API 키, 정답, 판정 로직)
```

- **레포:** 프라이빗 하나로 운영한다. 봉투 단어, 채점 프롬프트, 서버 로직이 공개되지 않게 하기 위해서다.
- **프론트:** Vite + React(또는 순수 JS). API와 같은 Cloudflare Worker가 정적 파일로 서비스하고, GitHub Actions가 자동 배포한다. (GitHub Pages는 무료 계정에서 프라이빗 레포를 지원하지 않아 쓰지 않는다.)
- **실시간 동기화:** Firebase Realtime Database와 익명 로그인.
- **서버 함수:** Cloudflare Workers 무료 요금제(하루 10만 요청). API 키는 정적 사이트에 둘 수 없으므로 Worker가 보관한다.
- **정답 보안:** 정답은 클라이언트가 읽을 수 없는 DB 경로에 두고, 유사도 계산과 정답 판정은 Worker에서만 한다.
- **정답 판정:** LLM을 쓰지 않는다. 정규화한 뒤 문자열이 같은지만 비교한다.

### 데이터 구조 (초안)
```
rooms/{code}
  settings: { hintLimit:10, timeLimitSec:900, autoStopAt:95, showSimToOthers:false,
              pieces:1, allowProperNouns:false }
  phase: "lobby" | "envelope" | "hinting" | "guessing" | "reveal" | "result"
  round, turnOrder[], currentSetter, hintStage(1~3)
  players/{uid}: { name, score, pieces, envelope, online }
  hints/{round}/{setter}/{stage}: { tries:[{word, sim}], chosen }
  guesses/{round}/{setter}/{stage}/{uid}: "단어"
secrets/{code}/{uid}: { r1Word, r2Word }      // 클라이언트 읽기 금지, Worker만 접근
simCache/{정답}/{단어}: { score, valid }       // 같은 쌍은 항상 같은 점수
```

## 4. 유사도 엔진 (Claude)

- **입력과 출력:** `{정답, 힌트 단어}`를 받아 구조화 출력 `{ score: 0~100 정수, valid: 명사인지, reason: 짧은 근거 }`로 답한다.
- **점수 기준:** 시스템 프롬프트에 구간별 기준과 예시를 고정한다. 95 이상은 거의 같은 말이나 동의어, 70~94는 같은 범주의 직접 연관어, 40~69는 연상되는 단어, 그 아래는 관계가 약한 단어.
- **일관성과 비용:** `(정답, 단어)` 쌍의 점수를 캐시하고, 처음 받은 값을 계속 쓴다.
- **프롬프트 캐싱:** 고정 프롬프트는 앞에, 바뀌는 단어는 맨 뒤에 둔다. 고정 부분은 캐시 최소 길이를 넘기도록 예시를 넉넉히 넣는다.
- **입력 검증:** 한글만, 1~15자, 공백 없는 단어만 받는다. 프롬프트 인젝션과 비용 악용을 막기 위해서다.

### 비용 추정 (한 판 기준, 프로토타입에서 다시 측정할 것)
가정: 6명 × 2라운드 × 평균 2차 힌트 × 힌트 후보 평균 6개 = 호출 약 150회 (최악 360회).

| 모델 | 1회당 | 한 판당 |
|---|---|---|
| Claude Opus 5.5 | 약 $0.004 | 약 $0.6 (최악 약 $1.5) |
| Claude Haiku 5.5 | 약 $0.0002 | 약 $0.02~0.03 |

## 5. 수익화

- **배너 수익:** 한 판에 6명, 노출 약 60회, CPM 약 $1로 잡으면 **한 판당 약 $0.06**. Haiku라면 비용이 메워지고, Opus로는 메워지지 않는다.
- **1단계, 하단 배너:**
  - AdSense는 `workers.dev` 같은 공용 하위 도메인으로는 승인이 까다로운 편이라 커스텀 도메인을 연결한다. 대안은 카카오 애드핏.
  - 개인정보처리방침, 이용약관, 문의 페이지를 둔다.
  - 라운드가 바뀔 때 배너를 새로 고친다. 모바일에서는 입력창과 겹치지 않게 배치한다.
- **2단계, 유료 판매 (수요 확인 후):**
  - 포트원이나 토스페이먼츠를 쓴다. 사업자등록, 통신판매업 신고, 환불 정책, 미성년자 결제 안내가 필요하다.
  - 결제가 끝나면 Worker가 웹훅으로 결제를 검증한 뒤 DB에 반영한다. 클라이언트는 피스 수를 바꿀 수 없다.
  - 승패에 영향을 주는 피스 판매는 유료 결제가 곧 승리가 되므로 신중히 정한다. 방 이용권, 방장 기능, 꾸미기 아이템을 우선 검토한다.

## 6. 비용과 한도 관리

| 위험 | 대응 |
|---|---|
| Firebase 무료 요금제 동시 접속 100명 제한 (6인 방 약 16개) | 접속 수 모니터링, 넘으면 종량제(Blaze)로 전환 |
| API 요청 악용 | 익명 로그인 토큰 검증, App Check, 사용자별·방별 호출 상한 |
| 갑작스러운 요금 증가 | Anthropic 콘솔 월 지출 한도와 알림. 넘으면 "오늘 서버 한도 초과" 화면 |
| Worker 요청 한도 | 하루 10만 요청이면 약 600판 분량 |

## 7. 개발 단계

1. **M1: 유사도 Worker.** Claude 호출, 구조화 출력, 쌍 캐시, 입력 검증. 테스트 페이지에서 Opus와 Haiku 점수를 비교하고 단가를 측정한다.
2. **M2:** Firebase 로비, 익명 로그인, 방 코드.
3. **M3:** 게임 진행 전체. 정답 판정은 서버에서.
4. **M4:** 타이머, 재접속, 결과 연출, 모바일 화면, 약관과 개인정보처리방침 페이지.
5. **M5:** 커스텀 도메인, 배포, AdSense 신청, 시험 플레이.
6. **M6 (수요 확인 후):** 사업자등록, 결제 연동, 이용권 상점.
